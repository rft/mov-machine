# Build and run

## Development shell

```sh
nix develop --impure
# Or use nix-direnv:
direnv allow
```

The shell uses `flake.lock` and installs Python dependencies from `uv.lock`. First entry downloads the Rust/Python/FPGA/formal toolchains. `devenv` may warn that the optional Cachix cache is not trusted; standard Nix cache downloads still work. No machine-wide settings need changing.

```sh
mkdir -p build
mov-assemble examples/copy.s build/copy.mov
mov-run build/copy.mov --max-steps 1000
```

Expected state:

```json
{"pc":11,"registers":[42,9,42,4294967288],"halted":true,"fault":false,"halt_code":42,"steps":10}
```

Direct Cargo equivalents:

```sh
cargo run --locked -- assemble examples/copy.s build/copy.mov
cargo run --locked -- run build/copy.mov --max-steps 1000
cargo run --locked -- exec examples/table-branch.s --max-steps 1000 --trace
```

`--max-steps` is required; infinite MOV-to-PC loops cannot hang the CLI. `--ram-words N` changes emulator RAM capacity (default 256). Successful explicit halt exits 0, independent of `halt_code`; a machine fault or exhausted budget exits 1; assembly/option/image/I/O errors exit 2. Errors are reported on stderr.

`--trace` writes a JSON object after each attempted instruction, followed by final state JSON. Trace rows add `memory_write: null` or `{ "address": ..., "value": ... }`, including successful PC/HALT MMIO stores. A faulting instruction has no memory-write event. The final row omits `memory_write`. Numeric fields are unsigned decimal.

The library exposes `assemble`, `Image`, `Instruction`, `Machine`, `State`, `StepOutcome` and `RunOutcome`. `Machine::step()` is architectural, not cycle-accurate; `Machine::run(max_steps)` returns a stop/budget outcome. `ram_mut()` permits host initialization. `reset()` clears CPU state/step count but preserves RAM. Raw images are decoded by execution, allowing malformed instructions to produce precise machine faults.

## Reference FPGA: iCEBreaker

```sh
mov-build build/copy.mov
# Produces build/icebreaker/mov_machine.bin, plus RTL, constraints and tool logs.
# Only with a connected board, explicitly program its flash:
mov-build build/copy.mov --program
```

Board: iCEBreaker, Lattice iCE40UP5K-SG48, 12 MHz board clock. The `amaranth-boards` platform supplies verified resource definitions and tool commands. Yosys synthesizes; nextpnr-ice40 places/routes; icepack creates the bitstream; `--program` invokes iceprog. No board is programmed by the default build.

The program is embedded in ROM, so changing it requires rebuilding the bitstream. Default RAM: 256 words; `--ram-words 1..1024` selects capacity. Reference ROM accepts 1–512 instructions. Actual resource fit and timing must be checked for each image/capacity, rather than inferred from those maximums.

* Green LED: successful explicit halt.
* Red LED: fault.
* Main user button: synchronized CPU reset; RAM persists until reconfiguration/power loss.

The board exposes status, not a UART console or runtime program loader. Inspect registers/halt code with the emulator or RTL simulation. No custom PCB is needed for this reference build. Electrical constraints are the board's 3.3 V resources; do not attach 5 V signals to FPGA pins.

Board-neutral exports:

```sh
mov-build build/copy.mov --emit-rtl build/mov_soc.il
mov-build build/copy.mov --emit-rtl build/mov_soc.v
```

Exports contain the core, synchronous ROM/RAM and architectural outputs; their clock/reset ports are generated by Amaranth. Use `MovCore` directly for a different memory system or `MovSoC` for a different board wrapper.

## Verification

```sh
mov-check
mov-formal
```

`mov-check` runs existing Rust behavioral tests, builds the CLI, assembles example/boundary/generated programs, and compares every architectural transition against both the real synchronous-memory SoC and a core with randomized bus stalls. It also checks stopped-state stability and reset cancellation/RAM persistence. Generated cases have a fixed seed; `--random-cases N` changes their number. It does not run formal proofs or place/route; those commands are separate.

For the precise formal claims and model bounds, see [formal verification](formal.md). For the compiler's current compatibility limit, see [compiler compatibility](compiler.md).

## Without the Nix shell

Install Rust 1.88 or newer and a native linker, Python 3.12 and uv; run `uv sync --frozen`, set `PYTHONPATH="$PWD/hw"`, and use `uv run python` for Python commands. RTL proofs additionally require compatible Yosys, sby and Z3; FPGA builds require nextpnr-ice40 and icestorm; abstract models require TLA+ and Alloy 6. The locked Nix shell is the exercised, reproducible path.
